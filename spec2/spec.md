# bluesky-marl 需求规范 v2.0

> 版本：v2.0
> 日期：2026-05-21
> 基于：spec.md v1.0 MVP + bluesky-gym 参考分析
> 定位：基于 BlueSky 仿真平台的多智能体强化学习环境

---

## 1. 项目定位修正

### 1.1 核心定位

本项目**立足于 BlueSky 仿真平台**，将其从单智能体环境（bluesky-gym）扩展为多智能体环境（PettingZoo ParallelEnv）。不局限于特定应用场景，而是构建通用的多智能体空管仿真基础设施。

### 1.2 与 bluesky-gym 的关系

bluesky-gym 是本项目的核心参考。它的 7 个环境覆盖了空管仿真的主要场景类型：

| 场景 | 特点 | 参考价值 |
|------|------|---------|
| horizontal_cr | 水平冲突解脱，航向机动 | 冲突检测逻辑、航向动作设计 |
| vertical_cr | 垂直冲突解脱，升降机动 | 垂直间隔标准、升降速率控制 |
| sector_cr | 扇区内冲突，航向+速度 | 扇区边界管理、多动作维度 |
| merge | 进近汇合，20 架飞机 | 高密度场景、最近邻观测策略 |
| descent | 下降阶段，无冲突 | 垂直导航、航路点跟踪 |
| static_obstacle | 静态障碍物规避 | 禁飞区建模、多边形区域检测 |
| plan_waypoint | 航路点导航 | 基础制导逻辑 |

### 1.3 多智能体扩展的核心差异

| 维度 | bluesky-gym | bluesky-marl |
|------|-------------|-------------|
| 智能体数量 | 1（ownship） | N（所有飞机均可控） |
| 动作空间 | 连续 Box | 离散 MultiDiscrete |
| 观测模式 | 全局观测 | 部分可观测（感知范围） |
| 冲突角色 | ownship vs intruders | 所有飞机互为对手 |
| 终止条件 | ownship 到达/碰撞 | 每个 agent 独立终止 |

## 2. V1.0 缺失功能补齐

### 2.1 到达目标终止

**现状**：飞机到达目标航路点后仅获得 +10 奖励，不会触发 episode 终止。

**需求**：当飞机到达目标航路点（距离 < 阈值）时，该 agent 的 termination 设为 True，并从活跃 agent 列表中移除。

**验收标准**：
- 飞机到达目标后，下一步不再出现在 agents 列表中
- terminations 字典中该 agent 为 True
- 其他未到达的 agent 不受影响

### 2.2 飞机动态进入空域

**现状**：episode 开始时生成固定数量的飞机，过程中只有移除没有新增。

**需求**：支持在 episode 过程中，新的飞机从空域边界进入。进入后自动加入 agents 列表，获得初始观测。

**验收标准**：
- episode 开始后，新的飞机可从空域边界进入
- 进入的飞机自动出现在 agents 列表中
- 进入的飞机获得正确的初始观测
- 进入时机和参数可配置

### 2.3 观测空间增强

**现状**：观测中方位角使用单一角度值，在 0/360 度边界存在不连续性。

**需求**：参考 bluesky-gym 的设计模式，增强观测空间：

- **方位角分解**：将方位角拆分为 cos 和 sin 两个分量，避免角度不连续
- **相对速度分量**：增加与其他飞机的相对速度信息（x/y 方向分量）
- **航向-目标偏差**：将当前航向与目标航路点方位的偏差分解为 cos/sin

**验收标准**：
- 方位角在 0/360 度边界无跳变
- 相对速度信息可用于判断冲突趋势
- 观测空间维度与配置一致

### 2.4 真实 BlueSky 集成验证

**现状**：所有测试使用 FakeBlueSkyWrapper，未验证真实 BlueSky API 调用。

**需求**：确保 BlueSkyWrapper 能正确调用 BlueSky API，完成完整的 reset/step 循环。

**验收标准**：
- 使用真实 BlueSky 可完成 reset（创建飞机）
- 使用真实 BlueSky 可完成 step（推进仿真、读取状态）
- 使用真实 BlueSky 可完成 close（清理资源）
- 飞机状态读取与 BlueSky 内部状态一致

### 2.5 仿真时间步长细化

**现状**：每个 env.step() 只调用一次 bs.sim.step()，RL 动作频率与仿真频率相同。

**需求**：参考 bluesky-gym 的 ACTION_FREQUENCY 模式，支持在每个 env.step() 中执行多次仿真步进，使 RL 动作频率低于物理仿真频率。

**验收标准**：
- ACTION_FREQUENCY 可配置
- 每个 env.step() 内执行多次 bs.sim.step()
- 飞机状态在多次步进后正确更新

## 3. V2.0 场景系统

### 3.1 场景基类

**需求**：实现场景基类，所有具体场景继承自基类。场景定义空域结构、飞机生成规则、冲突模式和终止条件。

**场景基类应支持**：
- 空域定义（边界、扇区划分）
- 飞机生成规则（数量、初始位置、初始状态）
- 冲突模式（对头、交叉、汇合、追越）
- 终止条件（到达、碰撞、超时、出界）

### 3.2 水平冲突解脱场景

**参考**：bluesky-gym horizontal_cr_env

**场景描述**：多架飞机在巡航高度层飞行，需要通过航向机动避免冲突并到达各自目标。

**关键参数**（参考 bluesky-gym）：
- 飞行器类型：A320
- 巡航速度：150 kt
- 冲突检测距离：5 NM
- 航路点距离：100-150 NM
- 动作维度：航向调整

**与 bluesky-gym 的差异**：
- 所有飞机均可控（而非仅 ownship）
- 使用离散动作空间（而非连续）
- 部分可观测（感知范围限制）

### 3.3 垂直冲突解脱场景

**参考**：bluesky-gym vertical_cr_env

**场景描述**：多架飞机在不同高度层，需要通过升降机动避免垂直冲突。

**关键参数**（参考 bluesky-gym）：
- 初始高度：2000-4000 ft
- 垂直间隔标准：1000 ft
- 水平冲突距离：5 NM
- 升降速率范围：±2500 ft/min
- 动作维度：升降速率调整

**特殊要求**：
- 同时检测水平和垂直间隔违反
- 两个间隔必须同时违反才算冲突

### 3.4 扇区冲突管理场景

**参考**：bluesky-gym sector_cr_env

**场景描述**：一个管制扇区内多架飞机同时飞行，需要管理冲突并维持安全间隔。

**关键参数**（参考 bluesky-gym）：
- 扇区面积：2400-3750 NM²
- 飞行密度：0.003-0.007 架/NM²
- 巡航高度：FL350
- 巡航速度：150 kt
- 冲突检测距离：5 NM
- 动作维度：航向 + 速度

**特殊要求**：
- 扇区边界为多边形（非矩形）
- 飞机离开扇区边界时截断（非终止）
- 支持动态飞机密度配置

### 3.5 进近汇合场景

**参考**：bluesky-gym merge_env

**场景描述**：一架飞机进近降落，需要与空中其他交通流保持安全间隔。

**关键参数**（参考 bluesky-gym）：
- 进近速度：100 kt
- 初始高度：10000 ft
- 汇合冲突距离：4 NM（比巡航场景更严格）
- 飞机总数：20 架（1 主控 + 19 背景交通）
- 可观测邻居数：5 架
- 动作维度：航向 + 速度

**特殊要求**：
- 背景交通不可控，按预设航路飞行
- 主控飞机需要找到安全间隙汇入
- 到达 Final Approach Fix (FAF) 为终止条件

### 3.6 静态障碍物规避场景

**参考**：bluesky-gym static_obstacle_env

**场景描述**：飞机需要绕过禁飞区到达目标航路点。

**关键参数**（参考 bluesky-gym）：
- 禁飞区：随机生成的多边形区域
- 冲突检测：飞机进入禁飞区即触发
- 动作维度：航向 + 速度

**特殊要求**：
- 禁飞区使用 BlueSky 的 areafilter 系统定义
- 进入禁飞区触发终止（非截断）
- 支持随机生成不同形状的禁飞区

### 3.7 航路点导航场景

**参考**：bluesky-gym plan_waypoint_env

**场景描述**：无冲突的纯导航任务，飞机按航路点飞行。

**用途**：
- 测试制导逻辑的正确性
- 作为无冲突基线
- 验证到达终止条件

## 4. V2.0 冲突解脱能力

### 4.1 冲突检测增强

**现状**：仅基于水平距离和垂直距离的简单阈值检测。

**需求**：增强冲突检测能力：

- **预测性冲突检测**：基于当前速度和航向，预测未来一段时间内的冲突概率
- **冲突等级细化**：在现有 NMAC/预警/间隔违反三级基础上，增加更多等级
- **多机冲突关联**：识别涉及多架飞机的连锁冲突

### 4.2 冲突解脱策略

**需求**：支持多种冲突解脱策略：

- **航向机动**：改变航向避开冲突（已有）
- **速度调整**：改变速度拉开时间间隔（已有）
- **高度调整**：改变高度层避开冲突（已有）
- **组合机动**：同时调整多个维度（已有）
- **优先级规则**：当多架飞机同时面临冲突时，按优先级决定避让方

### 4.3 安全间隔标准

**需求**：支持可配置的安全间隔标准：

- **水平间隔**：默认 5 NM，可配置
- **垂直间隔**：默认 1000 ft，可配置
- **时间间隔**：支持基于时间的间隔标准（如 3 分钟）
- **特殊场景间隔**：进近场景使用更严格的间隔（如 4 NM）

## 5. V2.0 流量管理能力

### 5.1 空域容量管理

**需求**：支持空域容量约束：

- **扇区容量上限**：每个扇区有最大同时在场飞机数
- **流量控制**：当扇区接近容量上限时，限制新飞机进入
- **容量配置**：每个扇区的容量可通过配置文件设定

### 5.2 航路网络

**需求**：支持航路网络建模：

- **航路点**：定义航路网络中的关键节点
- **航路段**：连接航路点的航路段
- **航路分配**：为每架飞机分配从起点到终点的航路
- **航路冲突检测**：检测不同飞机航路之间的潜在冲突

### 5.3 流量调度

**需求**：支持基本的流量调度：

- **起飞时序**：控制飞机从起点起飞的时间间隔
- **到达时序**：控制飞机到达终点的时间间隔
- **扇区移交**：飞机从一个扇区移交到另一个扇区时的协调

### 5.4 流量管理奖励

**需求**：新增流量管理相关的奖励组件：

- **延误惩罚**：飞机到达目标的时间超过预期时给予惩罚
- **容量违反惩罚**：扇区内飞机数超过容量上限时给予惩罚
- **流量效率奖励**：单位时间内通过扇区的飞机数越多，奖励越高
- **公平性奖励**：各飞机的延误时间越均衡，奖励越高

## 6. 配置系统扩展

### 6.1 场景配置

**需求**：每个场景有独立的配置文件，定义：

- 空域结构（边界、扇区、航路点）
- 飞机生成规则（数量、位置、状态范围）
- 冲突参数（检测距离、间隔标准）
- 奖励参数（各组件权重和阈值）
- 仿真参数（步长、最大步数、ACTION_FREQUENCY）

### 6.2 飞行器类型配置

**需求**：支持多种飞行器类型，每种类型有独立的性能参数：

- 速度范围（最小/最大/巡航速度）
- 升降速率范围
- 转弯速率
- 加减速性能

**默认飞行器类型**（参考 BlueSky 内置）：
- A320（大型客机）
- B737（中型客机）
- 可扩展支持更多类型

### 6.3 多场景支持

**需求**：支持在一个环境中切换不同场景：

- 通过配置文件选择场景
- 场景参数可在运行时覆盖
- 支持场景随机化（随机选择场景和参数）

## 7. 测试与验证

### 7.1 场景级测试

**需求**：每个场景有对应的集成测试：

- 场景初始化正确
- 飞机生成符合配置
- 冲突检测在场景中正确工作
- 终止/截断条件在场景中正确触发
- 奖励在场景中计算正确

### 7.2 真实 BlueSky 集成测试

**需求**：使用真实 BlueSky 运行的端到端测试：

- 每个场景可使用真实 BlueSky 运行
- 飞行动力学与 BlueSky 一致
- 命令执行与 BlueSky 一致

### 7.3 性能基准

**需求**：建立性能基准：

- 单步执行时间（不同飞机数量）
- 内存占用（不同场景规模）
- episode 完成时间（不同最大步数）
